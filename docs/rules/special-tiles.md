# 정령이 머무른 석판

> 조사 상태: 구현 참고 자료 확보, 교차 검증 진행 중
> 대상: 개편 전 고대 석판 파괴 방식
> 기준 구현: 초월 시뮬레이터 ver 1.8.0 (2024-10-07)

> 코어 구현: 6종 가중치 추첨, 파괴 효과, 재배치, 기존 표식 정리와 새 표식 배정 완료

## 조사 결과 요약

- 특수 석판은 6종이다.
- 정령 공격으로 해당 석판을 파괴해야 효과가 발동한다.
- 공격 처리가 끝나면 남아 있던 특수 석판은 일반 석판으로 돌아간다.
- 이후 남은 일반 석판 중 하나가 새로운 특수 석판으로 바뀐다.
- 아래 확률과 처리 순서는 공식 데이터가 아니라 당시 공개 시뮬레이터의 구현값이다.

## 특수 석판 6종

| 내부 ID 초안 | 표시 명칭 | 효과 | 시뮬레이터 확률 |
|---|---|---|---:|
| `SPIRIT_REROLL` | 추가 | 정령 교체 가능 횟수 +1 | 23.5% |
| `SPIRIT_SHUFFLE` | 재배치 | 활성 영역에 남아 있는 석판과 빈칸의 위치를 무작위 재배치 | 17% |
| `SPIRIT_SAVE_CHANCE` | 축복 | 이번 정령 소환 횟수가 증가하지 않음 | 11.5% |
| `SPIRIT_UPGRADE` | 강화 | 사용하지 않은 반대쪽 정령을 한 단계 강화 | 16% |
| `SPIRIT_COPY` | 복제 | 사용하지 않은 반대쪽 정령을 이번에 사용한 정령으로 교체 | 16% |
| `SPIRIT_MYSTIC` | 신비 | 사용하지 않은 반대쪽 정령을 신비 정령 중 하나로 교체 | 16% |

확률은 가중치 `47:34:23:32:32:32`, 합계 200으로 구현되어 있다.

2024년 공식 확률 공개 내용을 정리한 인벤 글은 `추가 23%`, `축복 11%`로
표현한다. 이는 소수점 버림·반올림인지 실제 확률 변경인지 원본 공식 페이지가
현재 삭제되어 확정할 수 없다. 따라서 구현 전까지 다음처럼 버전별로 보관한다.

```ts
const simulatorWeights = [47, 34, 23, 32, 32, 32]; // 2024-10-07 번들
const publishedSummary = {
  SPIRIT_REROLL: "23%",
  SPIRIT_SAVE_CHANCE: "11%",
}; // 2024-03-22 인벤의 공식 확률표 요약
```

## 효과별 상세 규칙

### 추가

- 정령 교체 가능 횟수를 1회 증가시킨다.
- 이번 턴에 정령을 사용한 횟수에는 영향을 주지 않는다.

### 재배치

- 보드의 플레이 가능한 모든 좌표를 대상으로 한다.
- 일반 석판, 왜곡 석판, 특수 석판뿐 아니라 이미 파괴된 빈칸도 함께 섞는다.
- 보드 외부로 표시되는 비활성 좌표는 섞지 않는다.
- 재배치 효과가 끝난 뒤 남아 있는 특수 석판은 일반 석판으로 정리된다.

따라서 구현에서는 석판 배열만 섞는 것이 아니라 `Tile | null` 상태 전체를 섞어야 한다.

### 축복

- 턴 시작 시 증가시킨 소환 횟수를 1 감소시켜 결과적으로 이번 턴을 소모하지 않는다.
- 공격과 석판 파괴 결과는 정상적으로 적용된다.
- UI 애니메이션과 엔진 이벤트는 `TURN_COST_REFUNDED`처럼 별도 이벤트로 표현하는 것이 좋다.

### 강화

- 이번에 선택하지 않은 반대쪽 정령의 레벨을 1 올린다.
- 이미 최고 레벨이면 변화가 없다.
- 그 뒤 사용한 정령 자리에 대기열의 다음 정령이 들어온다.

### 복제

- 선택하지 않은 반대쪽 정령을 이번에 사용한 정령의 종류와 레벨로 복사한다.
- 그 뒤 사용한 정령 자리는 대기열의 다음 정령으로 교체된다.
- 결과적으로 두 슬롯이 반드시 같은 정령으로 남는 것은 아니다.
- 다음 정령까지 같은 종류일 때에는 별도의 동일 정령 자동 합성 규칙이 이어질 수 있다.

### 신비

- 선택하지 않은 반대쪽 정령을 다음 중 하나로 교체한다.
  - 분출
  - 세계수의 공명
- 기준 시뮬레이터에서는 두 신비 정령을 동일 확률로 선택한다.
- 그 뒤 사용한 정령 자리는 대기열의 다음 정령으로 교체된다.

## 턴 처리 순서

기준 시뮬레이터의 동작을 엔진 단계로 풀면 다음과 같다.

1. 소환 횟수를 1 증가시킨다.
2. 정령의 각 공격 대상에 대해 파괴 여부를 추첨한다.
3. 왜곡 석판에 의한 일반 석판 재생성을 처리한다.
4. 벼락이면 무작위 추가 파괴 또는 재생성을 처리한다.
5. 이번 공격으로 파괴한 특수 석판의 효과를 적용한다.
6. 보드에 남아 있는 모든 특수 석판을 일반 석판으로 되돌린다.
7. 남은 일반 석판 중 하나를 골라 새 특수 석판으로 바꾼다.
8. 사용한 정령 슬롯에 대기열의 다음 정령을 넣는다.
9. 일반 석판이 모두 사라졌는지 성공 여부를 판정한다.
10. 상태 반영 후 두 활성 정령이 같으면 자동 합성을 판정한다.

애니메이션은 위 단계에서 생성된 이벤트를 순서대로 재생하되, 애니메이션이 실제
게임 상태를 변경해서는 안 된다.

## 동시에 여러 특수 석판을 파괴하는 경우

정상적인 턴 종료 후에는 특수 석판을 하나만 새로 생성하므로 일반 플레이에서는
여러 특수 석판이 동시에 존재하지 않는다.

기준 시뮬레이터 코드는 여러 개가 존재하는 비정상 보드에서 여러 특수 석판을 한 번에
파괴하면 마지막으로 순회한 석판의 효과 하나만 적용한다. 이는 게임 규칙이라기보다
“특수 석판은 최대 하나”라는 불변조건에 의존한 구현으로 판단한다.

우리 엔진에서는 다음처럼 명시적으로 제한한다.

```ts
type BoardInvariant = {
  maxActiveSpecialTiles: 1;
};
```

사용자 설정 보드나 테스트 데이터가 이 조건을 위반하면 조용히 하나만 실행하지 않고
검증 오류를 반환한다.

## 구현용 데이터 형식 초안

```ts
type SpecialTileId =
  | "SPIRIT_REROLL"
  | "SPIRIT_SHUFFLE"
  | "SPIRIT_SAVE_CHANCE"
  | "SPIRIT_UPGRADE"
  | "SPIRIT_COPY"
  | "SPIRIT_MYSTIC";

type SpecialTileDefinition = {
  id: SpecialTileId;
  weight: number;
  effect:
    | "ADD_REROLL"
    | "SHUFFLE_BOARD"
    | "REFUND_SUMMON"
    | "UPGRADE_OTHER_SPIRIT"
    | "COPY_USED_SPIRIT"
    | "REPLACE_OTHER_WITH_MYSTERY";
};
```

확률을 부동소수점 숫자로 직접 저장하지 않고 정수 가중치로 보관한다.
