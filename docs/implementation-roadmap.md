# 구현 로드맵

## 처음부터 잘 설계해야 하는 부분

다음 항목은 이후 UI, 애니메이션, AI가 모두 의존하므로 처음부터 구조를 고정한다.

- 규칙 엔진과 UI 분리
- 불변 게임 상태 전이
- 행동과 결과 이벤트 분리
- 타일 ID와 위치 분리
- 행동 턴과 정령 소환 횟수 분리
- 현재 정령 2개, 미리보기, 교체 횟수
- 정령 종류와 강화 단계를 수용하는 데이터 모델
- 타일의 선택적 특수 효과
- 특수 효과 해결 이벤트와 최대 1개 불변조건
- 시드 기반 독립 난수 스트림
- 단계 및 정령의 데이터 기반 정의
- 규칙 버전과 저장 스키마 버전
- 비동기 AI 추천 인터페이스
- 대전 단계와 선택 비공개
- 리플레이에 필요한 행동·이벤트 기록
- 가호가 반영된 공통 초기 상태

## 나중에 구현해도 되는 부분

연결 지점만 유지하면 이후 추가하거나 교체할 수 있다.

- 실제 Monte Carlo 및 다중 턴 AI
- Web Worker 또는 서버 계산
- 실패 횟수에 따른 엘조윈의 가호 자동 상승과 장비별 진행도 저장
- 모든 장비 부위와 1~7단계 데이터
- 로컬 저장, URL 공유, 계정 동기화
- 고급 애니메이션과 파티클
- 효과음과 배경음
- AI 캐릭터와 계산 연출
- 설명형 AI
- 전적, 랭킹, 일일 도전
- 이미지 인식

## 단계별 개발 계획

### 0단계: 규칙 자료 확정

목표:

- classic 규칙 범위 확정
- 정령 목록 작성
- 정령별 레벨 범위와 확률 수집
- 테스트용 실제 보드 하나 확정
- 특수 타일 생성·소멸과 연쇄 순서 검증
- 통합 턴 상태 전이 명세 작성

완료 조건:

- 규칙 데이터 표에서 모든 항목이 `확정` 또는 명시적인 `미확정`으로 표시된다.

### 1단계: 최소 규칙 엔진

구현:

- 일반 석판 보드
- 정령 하나
- 타일별 파괴 확률
- 시드 기반 난수
- 행동 이벤트
- 성공 판정
- 정령 소환 횟수와 등급

완료 조건:

- 같은 시드와 행동으로 항상 같은 이벤트와 결과가 나온다.

### 2단계: 최소 대전

구현:

- 동일 초기 설정
- 플레이어와 AI의 독립 게임 인스턴스
- 독립 경기 난수
- 임시 AI
- 양쪽 행동 공개 및 결과 비교

완료 조건:

- 같은 칸을 선택해도 양쪽 결과가 독립적으로 나올 수 있다.

### 3단계: 정령 큐

구현:

- 현재 후보 2개
- 다음 정령 미리보기
- 정령 사용 후 큐 진행
- 정령 교체
- 동일 정령 자동 합성
- 정령 강화 단계

완료 조건:

- 플레이어와 AI가 공격 또는 교체를 합법 행동으로 선택할 수 있다.

### 4단계: 핵심 특수 효과

순서:

1. 축복
2. 복제
3. 강화
4. 추가

완료 조건:

- 행동 턴과 소환 횟수가 올바르게 분리된다.
- 정령 슬롯 변경과 자동 합성이 올바른 순서로 동작한다.

### 5단계: 보드 변형

구현:

- 왜곡 석판
- 석판 생성
- 재배치
- 타일 이동 이벤트

완료 조건:

- 재배치 후에도 타일 ID가 유지되고 리플레이가 재현된다.

### 6단계: 전체 콘텐츠

구현:

- 모든 일반 정령
- 신비 및 특수 정령
- 모든 특수 효과
- 특수 효과와 카드 갱신·연쇄 합성
- 실제 단계 데이터

완료 조건:

- 선택한 대표 초월 단계 한 판을 원본 규칙대로 끝까지 진행할 수 있다.

### 7단계: 초파고 v1

구현:

- 합법 행동 전수 생성
- 행동별 Monte Carlo
- 클리어 및 3등급 확률
- 기대 잔여 석판
- 계산 취소와 시간 제한

완료 조건:

- AI 계산이 실제 경기 난수를 변경하지 않는다.
- 같은 상태와 AI 시드로 같은 추천을 재현할 수 있다.

### 8단계: 애니메이션과 분석

구현:

- 정령 소환
- 타격과 파괴
- 특수 효과
- 재배치
- 양쪽 동시 연출
- 판단 품질 및 운 분석

완료 조건:

- 애니메이션을 끄거나 배속해도 게임 결과가 변하지 않는다.

## 첫 번째 플레이 가능 목표

고정 테스트 보드에서 사람과 임시 AI가 정령 하나로 번갈아 선택하고, 양쪽 독립 난수로
석판을 파괴하며, 같은 시드를 사용하면 대전을 완전히 재현할 수 있는 상태.
