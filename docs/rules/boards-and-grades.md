# 부위·단계별 보드와 등급 기준

> 조사 상태: 시뮬레이터 데이터 추출, 인벤 자료와 부분 교차 확인
> 대상: 개편 전 고대 석판 파괴 방식
> 기준 구현: 초월 시뮬레이터 ver 1.8.0 (2024-10-07)

## 조사 결과 요약

- 부위는 무기, 투구, 어깨, 상의, 하의, 장갑 6종이다.
- 각 부위는 1~7단계의 고정 보드를 가진다.
- 보드 외곽 크기는 단계에 따라 6×6, 7×7, 8×8로 커진다.
- 실제 플레이 가능한 영역 모양은 부위별로 고정된다.
- 왜곡 석판의 초기 위치도 부위·단계별로 고정된다.
- 완료 시 사용한 정령 소환 횟수와 기준선으로 0~3등급을 결정한다.

## 좌표 기준

이 문서의 좌표는 구현용 0 기반 좌표다.

```text
(row, column)
왼쪽 위 = (0, 0)
오른쪽으로 갈수록 column 증가
아래로 갈수록 row 증가
```

UI에 표시할 때에는 필요하면 행·열에 각각 1을 더한다.

## 단계별 외곽 크기

| 단계 | 크기 |
|---|---|
| 1~3단계 | 6×6 |
| 4~5단계 | 7×7 |
| 6~7단계 | 8×8 |

## 부위별 활성 영역

`n`은 보드 한 변의 길이, `center = (n-1)/2`,
`d = |row-center| + |column-center|`이다.

| 부위 | 활성 좌표 조건 | 활성 칸 수 6×6 / 7×7 / 8×8 |
|---|---|---:|
| 무기 | `d <= n/2` | 24 / 25 / 40 |
| 투구 | `d <= n/2 + 1` | 32 / 37 / 52 |
| 어깨 | 전체 정사각형 | 36 / 49 / 64 |
| 상의 | `d <= n/2` | 24 / 25 / 40 |
| 하의 | 전체 정사각형 | 36 / 49 / 64 |
| 장갑 | `d <= n×2/3` | 32 / 37 / 52 |

무기와 상의, 투구와 장갑은 활성 칸 수가 같지만 왜곡 석판 배치는 서로 다르다.

## 등급 기준선

`cutline`은 3등급을 받을 수 있는 최대 정령 소환 횟수다.

| 단계 | 무기·상의 | 투구·장갑 | 어깨·하의 |
|---:|---:|---:|---:|
| 1 | 5 | 7 | 7 |
| 2 | 5 | 7 | 7 |
| 3 | 5 | 7 | 7 |
| 4 | 5 | 8 | 10 |
| 5 | 5 | 8 | 10 |
| 6 | 8 | 11 | 13 |
| 7 | 8 | 11 | 13 |

완료한 턴을 포함한 총 소환 횟수로 다음 등급을 계산한다.

| 완료 소환 횟수 | 결과 |
|---|---:|
| `count <= cutline` | 3등급 |
| `count === cutline + 1` | 2등급 |
| `count === cutline + 2 또는 +3` | 1등급 |
| `count >= cutline + 4` | 0등급 |

```ts
function calculateGrade(
  summonCount: number,
  cutline: number,
): 0 | 1 | 2 | 3 {
  if (summonCount <= cutline) return 3;
  if (summonCount <= cutline + 1) return 2;
  if (summonCount <= cutline + 3) return 1;
  return 0;
}
```

축복으로 소환 횟수를 소모하지 않은 턴은 `summonCount`에 포함되지 않는다.
정령 교체 역시 소환 횟수를 사용하지 않는다.

## 구현 구조

보드 모양과 왜곡 석판 위치를 하나의 거대한 2차원 배열로 중복 저장하지 않고,
활성 영역 생성기와 왜곡 좌표를 분리한다.

```ts
type BoardDefinition = {
  part: EquipmentPart;
  stage: 1 | 2 | 3 | 4 | 5 | 6 | 7;
  size: 6 | 7 | 8;
  shape: "DIAMOND" | "WIDE_DIAMOND" | "SQUARE" | "ROUNDED_DIAMOND";
  distortedPositions: Position[];
  grade3Cutline: number;
};
```

초기 보드는 다음 순서로 생성한다.

1. `size`와 `shape`로 활성 영역을 만든다.
2. 활성 좌표를 일반 석판으로 채운다.
3. `distortedPositions`의 석판을 왜곡 석판으로 교체한다.
4. 엘조윈의 가호가 있다면 별도 전처리를 적용한다.
5. 같은 완성된 초기 상태를 플레이어와 AI 인스턴스에 복제한다.

## 데이터 검증 규칙

```ts
function validateBoardDefinition(definition: BoardDefinition): void {
  // 모든 왜곡 좌표가 보드 안에 있어야 한다.
  // 모든 왜곡 좌표가 활성 영역이어야 한다.
  // 왜곡 좌표는 중복되면 안 된다.
  // 부위·단계 조합은 정확히 하나만 존재해야 한다.
  // cutline은 양의 정수여야 한다.
}
```

기준 시뮬레이터 코드에는 투구 6단계 `(3,5)`와 상의 6단계 `(2,2)`를 중복으로
대입하는 코드가 있다. 실제 결과에는 각각 한 개의 왜곡 석판만 존재하므로 이 문서에는
중복을 제거한 8개 좌표를 기록했다.

## 검증 상태

| 항목 | 상태 |
|---|---|
| 부위 6종·각 7단계 | 게임 설명·시뮬레이터 구현 일치 |
| 단계별 6×6·7×7·8×8 크기 | 구현 확인, 공략 화면 부분 확인 |
| 부위별 활성 영역 모양 | 구현 확인, 공략 화면 부분 확인 |
| 왜곡 석판 좌표 42세트 | 시뮬레이터 구현 추출 |
| 방어구 1단계 왜곡 석판 없음 | 인벤 공략·구현 일치 |
| 무기 1단계 왜곡 석판 4개 | 구현 확인 |
| 3등급 기준선 | 시뮬레이터 구현 추출 |
| 2·1·0등급 계산 | 시뮬레이터 구현 추출 |
| 축복·교체의 소환 횟수 제외 | 앞선 규칙 조사와 구현 일치 |

정확한 초기 보드 좌표와 등급 기준은 실제 게임 화면 전체 42세트를 확보하면 다시
대조한다. 현재는 당시 공개 웹 시뮬레이터의 최종 배포 데이터를 구현 기준으로 사용한다.
