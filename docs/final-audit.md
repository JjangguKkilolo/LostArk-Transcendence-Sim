# 초기 설계 문서 최종 감사

> 감사 대상: `docs/` 초기 규칙·제품·기술 문서 전체
> 감사 기준일: 2026-07-30
> 구현 대상 규칙: `classic-2024-07-24`

이 문서는 초기 설계 문서를 GitHub에 게시하기 전, 원작 재현 규칙과 프로젝트가
의도적으로 추가하거나 보정한 규칙을 분리해 기록한다.

## 결론

- 기준 규칙은 2024-07-24 완화 패치 이후부터 2024-12-18 개편 이전으로 일관되게
  고정했다.
- 당시 공개 초월 시뮬레이터 ver 1.8.0의 보드·정령·큐·특수 석판 구현을 현재
  재현 기준으로 삼았다.
- 공식 자료에서 확인할 수 없는 내부 추첨 순서는 시뮬레이터 동작을 채택하되
  `SIMULATOR_REFERENCE` 성격임을 유지한다.
- 현재 남은 불확실성은 엔진 구조를 다시 설계해야 하는 종류가 아니라, 명칭·확률
  가중치·세부 추첨을 규칙 데이터 버전으로 교체할 수 있는 종류다.
- 따라서 최소 규칙 엔진 구현을 시작할 수 있다. 다만 현재 문서를 “공식 원작의 완전한
  명세”로 표시해서는 안 된다.

## 감사 중 수정한 오류와 모순

| 항목 | 문제 | 수정 |
|---|---|---|
| 일반 정령 요약 | 10종 중 `대폭발` 누락 | 게임 규칙 요약에 10종 모두 반영 |
| 왜곡 석판 표현 | 비엘조윈 타격도 실제 파괴처럼 읽힐 수 있음 | 타격·복구와 실제 파괴를 구분 |
| 행동 타입 | 기술 설계는 `spiritId`, 통합 명세는 활성 슬롯 사용 | `activeIndex`와 `Position`으로 통일 |
| 행동 횟수 명칭 | `actionTurn`과 `actionCount` 혼용 | `actionCount`로 통일 |
| 가호 구조 | 일부 문서가 가호를 나중 기능으로만 분류 | 초기 상태에는 포함하고 자동 누적만 연기 |
| 특수 효과 | 복수 효과 우선순위를 구현하는 것처럼 표현 | 정상 상태 최대 1개, 위반 시 오류로 통일 |
| 종료 상태 | 기술 설계에 근거 없는 `FAILED` 상태 존재 | 게임 엔진은 `PLAYING`, `CLEARED`만 사용 |

## 원작과 동일하게 재현할 부분

다음은 현재 규칙 버전에서 게임 결과에 직접 영향을 주므로 임의로 바꾸지 않는다.

- 부위·초월 단계별 보드 모양과 초기 왜곡 석판 좌표
- 일반 정령 10종과 신비 정령 2종의 범위·확률
- 활성 정령 2장, 미리보기 3장, 교체 시 큐 전진
- 동일 정령 자동 합성과 최대 3레벨
- 일반 석판 0개일 때 성공하는 조건
- 비엘조윈 정령의 왜곡 석판 타격과 타격당 일반 석판 3개 복구
- 정화·세계수의 공명의 왜곡 석판 실제 파괴
- 특수 석판 6종의 효과와 한 턴 수명
- 축복을 적용한 소환 횟수 환급
- 부위·단계별 등급 기준
- 가호 단계별 왜곡 석판 일반화와 교체 횟수 증가

## 구현을 위해 의도적으로 보정한 부분

아래 항목은 원작 규칙을 바꾸려는 것이 아니라 웹 대전, 재현성, 오류 검출을 위한
프로젝트 자체 규칙이다.

### 결정론적 좌표 순회

원작 클라이언트의 내부 난수 소비 순서는 공개되지 않았다. 같은 시드와 행동을 항상
재현하기 위해 공격 추첨 좌표를 `(row, column)` 오름차순으로 고정한다.

이 보정은 개별 확률을 바꾸지 않지만 특정 시드가 만드는 정확한 파괴 좌표는 원작과
같다는 의미가 아니다.

### 시드 기반 다중 난수 스트림

원작에는 사람과 AI의 병렬 대전이 없다. 프로젝트에서는 다음 난수를 분리한다.

- 공통 초기 설정
- 플레이어 실제 경기
- AI 실제 경기
- AI 가상 탐색
- 결과에 영향 없는 애니메이션

따라서 같은 행동을 해도 양쪽 결과가 독립적이며, AI 계산량이 실제 결과를 바꾸지
않는다.

### 타일 ID와 이벤트 로그

원작 규칙에는 영구 타일 ID나 이벤트 로그라는 개념이 없다. 재배치 애니메이션,
리플레이, 디버깅을 위해 타일의 위치와 정체성을 분리하고 모든 중간 결과를 이벤트로
기록한다. 확률과 성공 판정에는 영향을 주지 않는다.

### 비정상 복수 특수 석판 거부

정상 진행에서는 활성 특수 석판이 최대 하나다. 참고 시뮬레이터는 비정상 입력에서
여러 특수 효과 중 하나만 남기는 구현 세부가 있지만, 이를 규칙으로 복제하지 않는다.
두 개 이상이 들어오면 불변조건 오류로 처리해 데이터 문제를 조기에 발견한다.

### 수동 가호 설정

첫 플레이 버전은 장비별 실패·완료 기록과 재화를 구현하지 않고 가호 0~10을 경기
설정에서 직접 고른다. 선택된 가호가 한 판에 주는 효과는 원작대로 적용한다.

### 대전 승패와 기권

원작 미니게임에는 초파고와의 승패, 라운드, 기권 규칙이 없다. 이는 제품 계층의
추가 규칙이며 단일 초월 게임 엔진과 분리한다.

## 아직 원작과 100% 같다고 단정할 수 없는 부분

| 항목 | 현재 채택값 | 위험과 처리 |
|---|---|---|
| 업화 명칭 | `업화` | 일부 자료의 `화염폭발`과 표기 차이. 내부 ID로 분리 |
| 신비 정령 한국어 명칭 | `분출`, `세계수의 공명` | 당시 번역 자료 중심. 표시 문자열 교체 가능 |
| 벼락 추첨 | `-1` 또는 `0..2×레벨`의 단일 균등 추첨 | 시뮬레이터 구현 채택. 규칙 버전 데이터로 격리 |
| 특수 석판 가중치 | `47:34:23:32:32:32` | 공개 요약의 23%·11%와 0.5%p 차이. ver 1.8.0 재현값 유지 |
| 특수 석판 생성·정리 시점 | 시뮬레이터 순서 | 실제 영상 전체 교차 검증 전까지 구현 기준값 |
| 합성 동률 슬롯 | 두 번째 슬롯 유지 | 시뮬레이터 내부 세부이며 최종 확률 분포에는 영향이 작음 |
| 빈칸 부족 시 왜곡 복구 | 가능한 빈칸만 복구 | 시뮬레이터 구현값, 원작 설명은 공간 부족 예외를 명시하지 않음 |
| 전체 42개 보드 좌표 | 시뮬레이터 추출값 | 실제 화면 42세트와 전수 시각 대조는 미완료 |

이 값들은 `rulesVersion`에 묶고, 출처가 더 강한 자료를 확보하면 새 규칙 버전을
추가한다. 기존 리플레이의 결과가 달라지므로 같은 버전 값을 조용히 수정하지 않는다.

## 구현 전 필수 안전장치

- 확률은 부동소수점 비교보다 정수 가중치로 저장한다.
- 모든 무작위 후보 배열은 추첨 전에 결정론적으로 정렬한다.
- 규칙 데이터에 출처와 `VERIFIED | SIMULATOR_REFERENCE | ESTIMATED`를 기록한다.
- 저장 파일에 `schemaVersion`, `rulesVersion`, 모든 시드를 기록한다.
- AI와 UI는 자체적으로 합법 행동이나 성공 여부를 계산하지 않는다.
- 대표 보드뿐 아니라 42개 보드 정의에 데이터 검증 테스트를 실행한다.
- 미확정 규칙으로 계산한 AI 수치를 공식 성공 확률처럼 표시하지 않는다.

특수 석판 확률은 공식 페이지가 2024-12-18 개편 값으로 덮어써져 클래식 상세 표를
현재 직접 열람할 수 없다. 따라서 기사에 표시된 정수값을 임의로 소수점 확률로
해석하지 않는다. `classic-2024-07-24`은 기준 시뮬레이터의 정수 가중치
`47:34:23:32:32:32`를 사용하고, UI와 문서에서는 해당 값이 시뮬레이터 기준임을
표시한다.

다음 항목은 2차 검색 후에도 독립된 원본 데이터 표를 확보하지 못했다.

- 부위·단계별 42개 보드의 전체 좌표
- 자동 합성에서 동레벨일 때 남기는 슬롯
- 특수 석판 정리와 카드 큐 갱신의 내부 실행 순서
- 왜곡 복구 시 빈칸 부족 처리

이 항목은 정확성 등급을 올리지 않고 `SIMULATOR_REFERENCE`로 유지한다. 엔진 구현은
가능하지만 공식 원작과 완전히 같다고 표시하지 않는다.

## 게시 판단

현재 문서는 다음 목적에는 적합하다.

- 초기 아키텍처와 개발 범위 합의
- 최소 규칙 엔진 구현 시작
- 조사 결과와 미확정 값의 버전 관리
- 사람 대 초파고 대전 프로토타입 제작

다음 목적으로는 아직 부족하다.

- 원작 클라이언트와 시드 단위 결과 일치 주장
- 모든 명칭이 공식 한국어 표기라는 주장
- 미확정 추첨값을 사용한 AI 확률의 공식성 주장
- 실제 재화 비용과 장비 성장 과정 전체 재현

따라서 GitHub에는 **초기 설계 및 시뮬레이터 기준 규칙 명세**로 게시한다.
